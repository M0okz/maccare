Guide · Confidentialité

Comprendre les accès et les connexions réseau.

MacCare fonctionne sans compte et sans télémétrie.

Ce qui reste local

Les analyses des fichiers et les rapprochements d’applications s’effectuent sur le Mac. L’historique de batterie et les réglages restent locaux. MacCare n’ajoute pas de compte ni de service de remontée de votre inventaire.

Les connexions déclenchées par les fonctions

  • La recherche de mises à jour de MacCare consulte son flux GitHub ; les recherches automatiques sont désactivables.
  • La recherche de mises à jour des autres apps interroge leurs sources : App Store, Homebrew ou flux officiel selon les cas.
  • Le catalogue hybride télécharge les métadonnées publiques Homebrew et fait les correspondances localement ; il interroge les exceptions officielles pour les apps concernées installées.
  • Le suivi des batteries Apple utilise une connexion locale USB ou Wi-Fi avec les appareils déjà approuvés. Les relevés restent en mémoire et ne sont pas envoyés à MacCare.
  • Le test Internet utilise Cloudflare lorsque vous le lancez.

Les services contactés reçoivent les informations ordinaires d’une connexion réseau, comme l’adresse IP. Sans télémétrie ne signifie pas sans aucune connexion réseau.

Les autorisations macOS

L’accès complet au disque ouvre la lecture de dossiers protégés. Certaines analyses restent partielles sans cet accès. L’assistant système facultatif demande une approbation distincte pour les opérations privilégiées.

L’outil Autorisations des applications permet d’examiner les informations disponibles et d’ouvrir les réglages concernés. Une réinitialisation d’autorisation efface une décision ; elle n’accorde pas automatiquement un nouvel accès.

Les composants embarqués

La détection App Store et la lecture SMART utilisent des outils embarqués dans MacCare ; vous n’avez pas à installer Homebrew pour ces fonctions. Leurs licences accompagnent l’application. Le code MacCare est publié sous licence MIT.
